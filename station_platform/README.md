# 场站 Agent 专用部署平台

首期版本：0.1.0，2026-10-13。

平台独立管理模型请求、工具执行、角色配置、任务和会话记录。中心与站级节点分别运行，运行代码不调用 Hermes。默认部署一个模拟场站和五个角色。

## 1. 当前可用内容

- 网页管理、模型连接、Agent 配置、角色对话、业务任务和过程监控。
- 每个角色的实际运行职责文档、草稿编辑、Markdown 预览、版本发布和只读历史。
- 运营商四个角色：O1 运营协调、O2 能源资源、O3 电价与运营优化、O4 虚拟电厂业务。
- 独立站级节点上的 S1 感知交互角色，五秒周期上报模拟状态，重要模拟事件触发事实查询与解释。
- Responses 和 Chat Completions 标准 API 适配。连接测试包含文本、函数调用和工具结果回传。
- 分时电价规划及虚拟电厂充电功率预算模拟，实际调用迁移的编排和评价算法。
- 站端本地校验、可推进的四时段模拟执行、逐时段回执及模拟业务反馈。
- SQLite 持久记录、任务提交幂等、计划及执行时段幂等、取消迟到发送保护、配置版本固定和重启恢复观察。

**业务数据与执行始终是模拟。真实模型 API 接入与模拟业务是两个独立维度。** 部署包不包含凭据，新安装需要配置。2026-10-13 本机实例已加密配置 DeepSeek V4 Pro，真实连接及 O1、S1 事实工具对话验收通过，详见 [验收记录](./验收记录.md)。没有通过测试的连接时，感知程序可运行，但任务和对话不会用测试替身伪装成真实模型成功。

## 2. 启动与停止

在项目根目录的 PowerShell 中执行。交付目录已建立独立虚拟环境；换电脑时先执行 setup。

```powershell
# 换电脑或重新建立环境时使用，可通过 -Python 指定本机 Python 3.13 路径
.\station_platform\run.ps1 -Command setup

# 后台启动中心与一个站级节点，服务窗口隐藏
.\station_platform\run.ps1 -Command start

# 查看进程身份及服务健康
.\station_platform\run.ps1 -Command status

# 停止本平台登记且进程创建时间匹配的进程
.\station_platform\run.ps1 -Command stop
```

默认网页为 [http://127.0.0.1:8780](http://127.0.0.1:8780)，站级服务为 `127.0.0.1:8781`。首期仅绑定本机地址。

独立管理某一服务：

```powershell
.\station_platform\run.ps1 -Command start -Only center
.\station_platform\run.ps1 -Command start -Only node
.\station_platform\run.ps1 -Command stop -Only node
```

`center`、`node` 命令可用于前台诊断。可通过 `-CenterPort` 和 `-NodePort` 指定端口。端口被其他进程占用时启动失败，不停止未知进程。

## 3. 首次配置模型

1. 打开“模型连接”，填写连接名称、API 基础地址、协议、提供方支持的模型名、凭据和请求超时。
2. 基础地址填写 API 根路径，例如 `https://api.openai.com/v1`，不追加 `/responses` 或 `/chat/completions`。
3. 保存后点击“测试连接与工具”。三步均通过后，点击“设为默认”。
4. 默认五个角色共用该连接；各角色可在“Agent 与工具”中覆盖模型连接。

模型提供方必须支持所选协议、函数调用及多轮工具结果回传。协议不兼容、HTTP 错误、超时或返回格式无效时明确报错，不切换到替身。新版不读取或复制原 Hermes 私有凭据。

DeepSeek 使用 `https://api.deepseek.com`、`Chat Completions` 和 `deepseek-v4-pro`。平台对官方地址启用思考模式，保留并回传模型的 `reasoning_content`，包括工具结果后的请求和后续用户消息。连接测试使用提示请求工具调用并校验实际参数，不发送该思考模式不支持的 `tool_choice=required`。依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。

模型密钥与节点令牌使用当前 Windows 用户的 DPAPI 加密存储。搬到其他电脑或用户下需要重新配置，不能将加密密文视为可直接移植的密钥。站级模型请求由中心网关转发，网关只允许已绑定的 S1 配置与工具。

## 4. 两条业务流程

### 分时电价规划

在“任务与运行记录”填写车辆编号、补能量、到离站分钟及优先级，提交后由 O1 组织 O2 资源评估和 O3 编排评价，登记并发布选定计划。S1 调用本地校验与模拟准备工具后，站端显示“模拟已准备”。

点击“推进一个时段”或“快速完成四时段模拟”。系统按工具给定功率计算电量和成本，分别记录业务时间与实际记录时间。四个时段均完成后，中心根据回执完成任务，不把接收或校验成功当作执行完成。

### 虚拟电厂预算模拟

选择“虚拟电厂功率预算模拟”，填写充电功率预算。O4 读取模拟业务条件，O2 提供资源，O3 在物理容量与额外预算内生成并评价方案，O4 记录模拟确认后由 O1 发布。执行完成后，O4 调用履约工具核对实际模拟峰值与预算。

预算是充电负荷约束，独立于物理并网容量，不会改写保护或设备边界。当前仅支持该模拟业务，调频快速跟踪、真实市场申报和结算未接入。

## 5. 对话与角色扩展

- 默认使用 O1，其他角色和新增角色可独立对话。
- 查询由事实工具提供依据。对话中的业务需求通过 `create_task` 生成结构化草稿，页面显示“到表单核对”，核对补能量、时间及优先级后再提交运行。
- 新增角色可选择已授权的注册工具，不可获得 O1 的计划发布权限。
- 发布职责文档或编辑模型、工具配置会增加角色版本号。每个任务和会话固定所用版本，新配置不悄悄改变正在运行的任务；要使用新配置请新建会话或任务。
- 工具代码由开发注册。网页不执行任意上传脚本或终端命令。

### 运行文档查看、编辑与发布

进入“Agent 与工具”，点击任一角色的“查看文档”。当前五个角色创建时使用的是代码模板初始化、数据库保存的职责正文，没有独立的 `AGENTS.md` 等文件。页面据实展示完整的实际正文、原始来源、角色版本、文档修订和保存位置，不补造未使用的 Hermes 文件。运行器追加的“平台角色编号”独立显示为只读信息。

“当前生效”可查看 Markdown 预览和逐字原始正文。“草稿编辑”提供编辑与实时预览；保存草稿不影响运行，刷新页面或重启中心后草稿仍保留。Markdown 预览支持标题、段落、列表、代码、引用和 HTTP(S) 链接；原始 HTML 按文本显示，不执行脚本或嵌入图片。

保存后点击“发布为新版本”，将这份已保存草稿发布为唯一有效正文，并增加角色版本。之后创建的会话和任务使用新正文；已有会话、任务和站端绑定快照仍保留原正文。“发布历史”保留首次登记及每次发布的原文，只供查看。

文档发布和角色配置更新均进行版本校验。多个标签页编辑或期间修改角色配置时，过期保存或发布会返回冲突，已保存草稿不被覆盖，页面中的编辑内容仍保留。使用“刷新版本信息”，展开比较当前生效正文和服务器草稿，确认后重新保存再发布。刷新版本信息本身不会发布正文。

原职责编辑框已合并到文档页。角色配置页只管理名称、模型、启用状态、交互轮数和工具权限；新增角色时填写的初始职责登记为首版文档。文档内容不能突破程序中的工具授权、现场校验及固定业务流程。Skill、MCP 本轮不扩展。

## 6. 异常、取消与重启

“总览与场站”提供恢复正常模拟、容量下降、桩故障、保护事件、暂停心跳、量测过期、新增模拟桩和电价变化等预设场景。

- 心跳超过 15 秒未收到时显示离线；过期量测或质量不足不能支持新任务。
- 现场条件不满足时拒绝计划，不静默限幅后执行。
- 未开始执行的受限计划最多用新快照重算两次。重新发布使用新版本及新计划编号，历史工具结果与拒绝依据保留。
- **已有部分模拟执行时，保留已执行回执并停止自动重跑。** 首期迁移算法尚不支持保护已执行部分的增量编排，不能将全部原需求再次运行来代替剩余任务规划。
- 取消作用于剩余模拟；已完成的时段不会撤销。取消记录可阻止同一编号的迟到计划启动执行。
- 发布前任务在中心重启后标记中断；已登记发布编号的任务恢复观察，不自动再发。
- 站端重启时保留计划和时段记录，将未完成计划标为中断，不自动重新执行。

失败、受限和中断任务可以查询证据；首期没有自动重试真实模型失败的机制。用户修改条件后建立新任务。若外部模拟反馈阶段失败，执行完成回执仍保留，任务明确说明“执行完成、反馈失败”。

## 7. 默认限制

| 项目 | 首期默认 |
| --- | --- |
| 场站数量 | 一个，`mock-station-001` |
| 规划窗口 | 一小时，四个 15 分钟时段 |
| 车辆 | 1～12 辆，模拟受电能力 200 kW，无充电损耗 |
| 设备服务模型 | 单桩连续充电，保护服务承诺 |
| 储能 | idle，不安排储能充放电 |
| 能源预测 | `not_used`，使用明确标记的模拟资源序列 |
| 搜索 | 每种策略最多 50,000 次；搜索超限不等同于无解 |
| 活动任务 | 同站同一时段一个，电价与预算业务共用占用约束 |
| 模型请求 | 120 秒，模型连接页面可调整 |
| 角色工具轮数 | 12 轮，可在角色配置中调整 |
| 整项任务 | 30 分钟，可在模型连接页面调整 |

计算只比较搜索生成的候选，不能声称全局最优。模拟资源和成本不代表现场能力或实际节省。

## 8. 数据、接口与目录

`data/center.sqlite3` 保存连接版本、角色、会话、任务和工具事件；`data/node.sqlite3` 保存本站配置、计划及回执。`data/node-identity.json` 为加密节点身份；`data/processes.json` 为本平台进程身份记录；两个 `.log` 为服务日志。

当前有效文档正文仍只存于 `agents.prompt`；文档元信息、草稿、只读发布历史分别记录在中心数据库的 `agent_document_meta`、`agent_document_drafts`、`agent_document_history` 命名空间。首次登记不改写现有正文或角色版本。发布正文、更新角色版本、记录历史及消费草稿在同一事务中完成，失败全部回滚。部署前本机中心数据库备份位于 `data/backups/20261013-agent-documents/`，运行数据及备份不包含在部署包中。

运行数据和虚拟环境在 `.gitignore` 中排除。五类业务对象对应状态、能力、计划、回执和事件，均带有模拟来源以及适用的时间、版本和引用。

主要接口：

| 类别 | 接口入口 |
| --- | --- |
| 模型 | `/api/models`、`/api/models/{id}/test`、`/api/settings` |
| 角色与工具 | `/api/agents`、`/api/tools` |
| 实际运行文档 | `GET /api/agents/{id}/documents`、`PUT /api/agents/{id}/documents/instructions/draft`、`POST /api/agents/{id}/documents/instructions/publish` |
| 对话 | `/api/sessions`、`/api/sessions/{id}/messages` |
| 任务 | `/api/tasks`、任务详情、`events`、`stream`、`advance`、`cancel` |
| 站点 | `/api/station`、`/api/station/scenario` |
| 节点专用 | `/internal/station/heartbeat`、`/internal/model/turn`、站端 `plans` 接口 |

网页写入请求需要页面令牌和本机来源；节点接口需要节点令牌。模型凭据不在公开接口响应或事件中返回。角色配置与工具权限在后端校验，不依赖网页按钮限制。

文档查询仅返回角色实际登记的“运行职责”，`filename` 为 `null`，不开放任意路径读取。保存草稿提交 `body`、`base_agent_version`、`base_document_revision`、`expected_draft_revision`；发布提交同样三个版本字段，使用服务器已保存正文。正文非空且不超过 24000 字，保留空白和换行。版本冲突返回 HTTP 409，不允许增加权限字段。

角色查询继续提供兼容的 `prompt` 字段。`PUT /api/agents/{id}` 更新配置时需携带 `expected_version`，不能用不同的 `prompt` 绕过文档发布；`POST /api/agents` 创建新角色仍接受初始 `prompt`，与首版文档原子登记。

## 9. 验证

```powershell
.\station_platform\run.ps1 -Command test
```

测试会在独立 QA 数据目录启动本机中心、站端及**明确标记的模型测试替身**，通过实际 HTTP 验证两种模型协议、两个模拟业务闭环、权限、错误、幂等、DPAPI、配置版本和实际服务重启。

这些结果验证平台执行和协议处理，不证明真实提供方可用。提供有效模型连接后，须在网页完成连接测试、事实查询及两个业务任务的真实模型验收。当前实测结果见[验收记录](./验收记录.md)。

## 10. 迁移依据与后续扩展

`legacy/` 为原 `station_poc` 的需求适配、补能编排和评价算法迁移副本，不导入原运行器、部署脚本或 Hermes 插件。源文件与迁移文件的哈希见 `migration.json`。编排器增加独立的充电功率预算参数，其余计算口径保留。

下一阶段可接入已有光伏与负荷模型的只读推理，再开发储能资源计算、增量滚动编排和实际站点接口。多站、服务器部署、真实控制及生产运维应按独立验收阶段推进。
