# 光伏预测独立模型包

这是能源协同 Agent 的独立光伏功率预测模块。它只生成预测记录和模型评估证据，不修改并网容量、保护边界、SOC 保留或任何设备控制状态。

## 输入格式

默认输入为 CSV 或 Excel，至少包含：

```text
timestamp,pv_power_kw
2025-01-01T00:00:00+08:00,0
```

历史气象用 `--history-weather-columns` 指定，黄花站默认包含 `SWGDN,temperature_c,cloud_cover`。历史特征只取预测起点之前的观测。未来气象用独立的预报归档提供，详见下文，不能从同步观测表自动取值。参考数据使用其他列名时，必须通过 CLI 显式指定映射；`pv_kwh` 只有在同时指定区间长度后才会转换成 kW。短缺口只沿用先前观测填充，长缺口整段保留为空；不从预测起点之后的观测反向插值。

## CLI

### 直接运行完整训练

```powershell
python 运行.py
```

默认使用黄花站 2025 年 15 分钟**模拟数据**，先进行三段滚动验证、比较三组 GRU，再从头训练最终候选。历史分支输入过去 3 天（288 点）的功率、辐照、温度和云量；未来分支输入日历周期和计算得到的太阳高度角，输出未来 24 小时（96 点）。黄花站使用模拟数据配置的近似坐标（30.90°N、111.35°E），来源写入元数据，不能当作实站核验坐标。自定义数据请显式提供 `--latitude`、`--longitude`；没有坐标时不计算太阳高度角。默认不使用未来天气预报。

需要安装 `requirements.txt` 中的依赖及 TensorFlow（例如 `python -m pip install tensorflow`）。TensorFlow 对纯基线 CLI 是可选项，对 `运行.py` 的完整训练是必需项。

- 默认滚动分区为 1—4 月训练/5 月验证、1—6 月训练/7 月验证、1—8 月训练/9 月验证。每段独立拟合三个缩放器（目标、历史特征、未来特征）、重新初始化网络；每个目标窗口完全位于所属分区，历史上下文可来自之前时段。不打乱窗口。
- 三组 GRU 使用相同增强输入，隔离学习率和容量的影响：`gru32_control` 为 32 单元、LR 0.001、固定学习率、最多 30 轮、patience 5；`gru32_scheduled` 为 32 单元，`gru16_scheduled` 为 16 单元，两者 LR 0.0003、最多 50 轮、patience 8。此前生成的旧版模型文件仍保留。
- 调度组的验证损失连续 2 轮未显著改善时，学习率减半，最低 0.00001；早停与调度的 `min_delta=0.00001`（归一化 MSE）。日志 `LR=本轮 → 下一轮` 展示学习率变化。耐心计数按显著改善重置，最终权重保存实际最低验证损失的轮次。
- 默认全部有效训练窗口参与；三组候选都与持久性、前一日、同刻均值基线比较。选模按各段验证样本合并后的 RMSE，额外报告各段及合并的全天/白天 MAE、RMSE、R²、最差分区 RMSE；不对各段 RMSE 或 R² 简单取平均。稳定性指标用于检查，不暗示已经达到未经约定的生产门槛。
- 选模完成后才进行最终训练和测试报告。最终仍按 70% / 15% / 15% 切分：训练 255.5 天、验证和测试各 54.75 天；有效窗口数分别为 24,145、5,161、5,161（完整黄花站数据）。保留最后 15% 不参与滚动选模；它此前已被查看，因此本轮明确标记为回顾性测试，不能声称是新的独立验收。新的真实或未使用数据仍是最终验收所需条件。
- 每轮显示训练/验证 loss、训练 RMSE/R²、验证 RMSE/MAE/R²、学习率、早停计数和耗时。loss 是归一化 MSE，RMSE/MAE 是还原后的 kW；R² 对整组样本累计统计，常数标签的 R² 显示 N/A。有坐标时白天按太阳高度角大于零确定；无坐标时为 05:00—21:00 的近似时段。
- 训练指标是本轮更新权重过程中的在线累计值；验证指标使用该轮结束时的固定权重计算。训练结束后才输出留出测试集指标。指标汇总包含滚动预测窗口，重叠时刻按各预测起点重复计分；nRMSE 的分母为标签平均绝对功率。
- 即使基线在滚动验证中胜出，最佳 GRU 候选的最终权重、训练历史和测试指标仍然保存。`forecast.json` 使用滚动验证选中的模型。TensorFlow 缺失或训练分区不足时明确报错。

输出保存到新的 `运行结果/<时间戳>/`：

| 文件 | 内容 |
| --- | --- |
| `training.log` | 数据分区、逐轮日志、最终 RMSE/MAE/R²/nRMSE/区间覆盖率 |
| `rolling_validation.json` | 每段六组候选结果、合并指标、最差分区、选中配置和测试隔离信息 |
| `experiments/<分区>/<候选>/` | 每次滚动训练的权重、缩放器、特征、分区、日志、逐轮指标与 loss 图 |
| `training_history.csv` / `.json` | 最终候选的逐轮损失、指标、实际/下一轮学习率和耗时，每轮写入 |
| `training_summary.json` | 实际训练轮数、最佳轮次、早停原因及训练图引用 |
| `gru.keras` / `scalers.joblib` | 最佳 GRU 权重与训练集缩放器；每次验证损失改善保存模型 |
| `data_split.json` / `training_config.json` | 分区范围、有效窗口数与可复核训练参数 |
| `visualizations/training_loss.png` | 训练与验证损失曲线，每轮刷新 |
| `visualizations/gru_test_comparison.png` | 测试集前 7 个不重叠预测窗口：实际功率、GRU、最佳基线 |
| `metrics.json` | 选中模型和 GRU 的完整留出测试指标 |
| `forecast.json` / `evaluation.json` | 数据结束后未来一天预测、末日回测及各自图片引用 |

训练期间即可查看 CSV 和已刷新的 loss PNG，不会弹出阻塞训练的窗口。R²、RMSE、MAE 在运行日志展示并保存为数值记录，不另生成指标图或指标柱状图。`evaluation.json` 是最后一天的回测，完整测试集指标看 `metrics.json`。当前 Windows 环境使用 CPU，耗时随硬件变化；终端每 30 秒最多补充一次批次进度。

可以显式修改参数；限制样本的运行属于调试，不等于完整数据训练：

```powershell
python 运行.py --single-split --epochs 50 --patience 8 --units 32
python 运行.py --epochs 2 --max-gru-samples 32  # 三段对照流程冒烟，不代表完整训练
```

在本目录执行：

```powershell
python -m pv_forecast.cli train --input data.csv --output-dir model_bundle
python -m pv_forecast.cli predict --input recent.csv --bundle-dir model_bundle --output forecast.json
python -m pv_forecast.cli evaluate --input labelled.csv --bundle-dir model_bundle
```

只验证或使用基线时可跳过 GRU：

```powershell
python -m pv_forecast.cli train --input data.csv --output-dir model_bundle --skip-gru
```

CLI `train` 默认是一组调度 GRU：全部窗口、最多 50 轮、batch 128、32 单元、patience 8。添加 `--rolling-validation` 执行与 `运行.py` 相同的三组对照；`--folds` 可指定自定义分区。`--max-gru-samples` 为 0 表示全部，正数是显式调试限制。`--learning-rate`、`--lr-patience`、`--lr-factor`、`--min-lr`、`--min-delta` 配置调度；单组训练的 `--no-reduce-lr` 可关闭调度。`--require-gru` 禁止 GRU 不可用时静默退化；`--quiet` 仅关闭终端进度。训练日志走 stderr，stdout 保留 JSON。

项目当前已有的黄花站数据可以直接使用：

```powershell
$pvData = "..\数据\光伏数据\黄花站_2025年_15分钟光伏模拟数据.csv"
python -m pv_forecast.cli train `

```

该文件已是 15 分钟粒度，无需列名映射。上例坐标仅用于此模拟数据。预测时自动从模型元数据恢复训练时的历史特征、坐标和未来特征配置，保持缩放器和列顺序一致。

旧版 `.keras` 若仅因 `GlorotUniform` 的 `input_axes/output_axes=null` 字段无法读取，会在临时副本中移除这两个空默认字段后重试，原始文件和权重不变。非空字段或其他加载错误仍按模型不可用处理。建议训练与预测保持相同依赖版本；该兼容处理不代表任意 Keras/scikit-learn 版本都能互换。

### 可选的未来气象预报接口

归档必须是一站数据，CSV/Excel 含 `issued_at`（发布时间）、`timestamp`（预报对应时刻）和指定气象列。例如：

```text
issued_at,timestamp,SWGDN,temperature_c,cloud_cover
2025-06-01T00:00:00+08:00,2025-06-01T12:00:00+08:00,600,28,0.3
```

训练、预测、评估都支持 `--future-weather-input forecasts.csv --future-weather-columns SWGDN,temperature_c,cloud_cover`（`--weather-columns` 是未来列名的兼容别名）。训练需有覆盖训练期的历史预报归档；仅有当前预报不能用于历史回测。每个预测起点只选择 `issued_at <= 起点` 的最新一批预报，并要求该批完整覆盖未来 96 点；不混合不同发布批次，不使用起点之后发布的修订预报。发布时间保存在训练特征记录/元数据及预测 `confidence.weather_forecast_issued_at` 中。

Python 调用使用 `train_model(..., future_weather_source=...)`、`train_experiment(...)`、`predict_record(...)`、`evaluate_bundle(...)` 的同名参数。尚未取得真实预报时不启用未来气象列；不会自动将同步观测当作预报。预测缺少必要气象或权重时，使用已验证基线及该基线独立校准的区间，并标记 `degraded`；无验证基线则返回 `unavailable`。功率历史缺口或不能衔接预测起点时返回不可用。

输入质量摘要的 `missing_history_weather_columns` 列出缺失的历史气象列；缺少整列时，`missing_weather_rows` 计入所有受影响行，而不是记为零。

显式指定 `--forecast-start` 做历史回放时，数值校验、缺口填充和质量统计只处理起点之前的观测。起点后的功率和天气行不会修补末尾历史缺口，也不会改变输入质量或预测。没有起点前观测时返回 `unavailable`。数据加载API可用 `available_before=...` 表达相同的排他时间边界。

预测固定为未来 24 小时、15 分钟粒度，共 96 个点。训练使用时间顺序切分，先比较持久性/前一日/同刻均值基线，再在数据量足够且 TensorFlow 可用时训练双输入 GRU。预测区间由验证集残差校准。

`predict` 写出的 JSON 同级会生成 `visualizations/` 目录，默认包含未来 24 小时预测区间、历史与预测衔接、日内功率分布三张 PNG，并通过 `visualizations` 字段记录相对路径。`evaluate --output` 还会生成实际值与预测值对比图。

当前阶段没有真实历史数据，模型包不会自动创建生产发布权重。训练生成的 bundle 标记为 `candidate`，必须经过真实数据评审后才可发布。

## 昼夜分组区间与已有权重再校准

原区间按预测提前步数混合白天和夜间残差。光伏夜间残差通常较小，混合后的名义80%区间可能在全天接近80%，但白天明显欠覆盖。新增 `daylight` 选项，按**目标采样时刻**的昼夜分别校准；有坐标时用太阳高度角大于零，无坐标时用05:00—21:00近似时段。分组不读取未来功率或同步天气观测。

每组每预测步至少30个有限残差时使用该步分位数，否则使用同组汇总分位数；整个组无样本时明确记录 `unconditioned` 回退。校准JSON保留每组逐步样本数和回退来源。推理和GRU故障回退均按同一目标时刻掩码应用区间，基线仍使用自己的残差校准。旧模型包继续使用原混合区间；训练默认也保留 `pooled`，可显式添加 `--interval-conditioning daylight`。

已有候选可复用冻结权重和缩放器，不启动训练：

```powershell
python -m pv_forecast.cli recalibrate `
  --input "..\数据\光伏数据\黄花站_2025年_15分钟光伏模拟数据.csv" `
  --bundle-dir "运行结果\20260929_000009_045346" `
  --output-dir "运行结果\新的昼夜校准目录"
```

输出目录必须不存在，且位于父模型包之外；源包保持不变。命令按父包保存的时间边界重建全部验证窗口，先冻结主模型和基线区间，再读取完整测试窗口进行回顾性评价。分区缺失、有效窗口数不匹配、主模型不能加载时直接失败，不能用降级预测冒充完成校准。`--nominal-coverage` 可调整名义覆盖率，`--min-step-samples` 可调整逐步门槛。

新包包含 `model_metadata.json`、`interval_calibration.json`、`metrics.json`、复制的权重/缩放器及 `recalibration_report.json`。报告保存父包/数据哈希、完整分区边界、全天/白天/夜间覆盖率和平均区间宽度，模型版本增加 `+daylight-interval-v1`。使用原 `predict` 和 `evaluate` 命令即可加载新包。再校准本身不产生新的训练历史或图片。

2026-10-09 完整模拟数据实验保存在 `运行结果/20261009_daylight_recalibration_01`。同一冻结GRU和同一5161个测试窗口：白天覆盖率49.05%→83.00%，白天平均区间宽度约1108.15→1696.47 kW；夜间覆盖率99.60%→71.58%，全天覆盖率78.14%→76.43%。点预测RMSE仍为444.20 kW。这个候选改善了白天欠覆盖，但夜间发生欠覆盖，不能宣称整体优于原方案。原验证段也用于GRU早停，重叠窗口彼此相关，分组经验区间不保证未来覆盖率；需要新的实测或未使用数据才能独立验收。

### 可选的夜间零下界

GRU在夜间仍可能输出正功率，窄的经验残差区间因此可能排除零。新增 `--night-lower-bound zero`，在昼夜分组区间上将夜间下端点设为0，上端点、白天区间及所有点预测保持原值。这一操作只扩大夜间区间，不会减少原有覆盖；它不保证覆盖所有正的夜间实际值，也不改善点预测误差。昼夜判断仍依赖坐标或近似时段，真实场站需要核验夜间功率口径。

```powershell
python -m pv_forecast.cli recalibrate `
  --input "..\数据\光伏数据\黄花站_2025年_15分钟光伏模拟数据.csv" `
  --bundle-dir "运行结果\20260929_000009_045346" `
  --output-dir "运行结果\新的夜间零下界目录" `
  --night-lower-bound zero
```

训练时需同时指定 `--interval-conditioning daylight --night-lower-bound zero`。训练默认仍为原混合区间和 `empirical`；再校准未指定夜间策略时继承父包，旧包按 `empirical` 处理。策略写入主模型及故障基线自己的校准JSON、配置和预测记录。零下界候选版本增加 `+daylight-zero-lower-v1`。

已完成候选 `运行结果/20261009_night_zero_lower_01`：同一2025年回顾测试的白天覆盖仍为83.00%，夜间提升到100%，全天92.79%；夜间平均宽度43.84 kW。冻结权重、缩放器和点预测均未改变，CLI及回退验收见其 `verification/verification.json`。

## 冻结模型全窗口评估

`backtest` 比较相同输入/窗口契约的冻结模型，逐个15分钟起点评价所有完整历史和目标窗口，不训练、不选模、不再校准。批大小只影响内存和推理吞吐，不限制样本。共用相同预测器/缩放器的候选复用点预测，各自应用已保存区间。指标累计误差、标签和覆盖数，不对分批RMSE或R²取平均。

```powershell
python -m pv_forecast.cli backtest `
  --input "开发验证\20261009_night_support\frozen_2026_01\黄花站_2026年_15分钟_冻结评估模拟数据.csv" `
  --bundle-dir "运行结果\20260929_000009_045346" "运行结果\20261009_daylight_recalibration_01" "运行结果\20261009_night_zero_lower_01" `
  --output "运行结果\新的冻结评估报告.json" `
  --batch-windows 1024
```

该评估严格使用主模型，无法加载时失败；缺失的目标行不作为补值真值计分，最后历史观测缺失也排除该起点。其余历史完整性及预报归档条件沿用窗口构建逻辑。报告包括有效/排除起点、全天/白天/夜间、目标月份、白天提前步数组指标和均值偏差；输入存在 `weather_type` 时只在预测后用于分天气评分，不能作为未来模型输入。重复目标时刻按各预测起点计分，计分标签不是独立样本数。CLI使用的 `--output` 应为新的报告路径。

## 冻结GRU的可选点预测修正

`correct-point` 保留原GRU配置、权重、缩放器及九组完整训练证据，只拟合一个新的线性修正层。输入是原GRU预测、前一日/同刻均值、最近1点/1小时/6小时/24小时的历史功率与气象摘要、未来日历与太阳位置，以及太阳高度和历史摘要的交互项。同步的未来天气观测及 `weather_type` 标签不进入修正特征；它没有增加未来气象预报信息。

修正层对96个提前步分别用白天训练样本拟合标准化Ridge，所有原训练窗口参与，分批累计充分统计量以控制内存。标准化与回归参数都只从对应训练分区取得。默认候选正则系数为0.001/0.01/0.1，在原选中GRU类型对应的5/7/9月冻结权重上验证。按合并全天RMSE选择，同时要求白天合并RMSE和最差分区全天RMSE改善；没有满足条件的修正时保留原GRU。原三组GRU的模型选择不重新进行，九组训练产物必须完整存在，不能用限样训练产物冒充。
