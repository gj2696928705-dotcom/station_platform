# 黄花站需求响应技术模拟数据

本包按 D04 的**无业务规则分支**生成。已检查 D04、A09 及现有平台资料，没有可核实的市场基线、通知、考核、结算或授权规则版本。因此只测试相对冻结无响应模拟计划的技术响应与恢复，`market_rule_status=unknown`、`settlement_reference.status=not_applicable`；不代表市场准入、可报价能力或履约合格。

运行：

```powershell
python -B .\generate_dr_data.py
python -B .\validate_dr_data.py
```

`simulation_config.json` 固定 D01/D02、储能参数与交接文档的 SHA-256；`source_manifest.json` 和 `rule_sources.json` 记录来源。所有新文件留在本目录。CSV 为 UTF-8 BOM、LF，时间为北京时间 `+08:00`。字段详见 `字段字典.md`。

## 基线、实际与时间

同一模拟站点、同一 D01 `S06_calibration` 的 10:00–11:00 四个 15 分钟段。`baseline_plan.csv` 在 10:00 冻结，基础负荷只取 D01 决策前已完成时段构造的预测；D02 正常执行夹具中已接受的两车服务合计 80 kW 明确作为既有模拟承诺，另有两辆 DR 模拟车默认各 40 kW。储能闲置、PV 使用为 0、净取电由四项功率平衡算出。该无响应基线只是技术夹具，未按未知市场规则计算，也未把未来历史充电真值塞进决策输入。每个场景的完整基线有固定 SHA-256 指纹。

`execution_truth.csv` 是 D01/D02 同期**事后**站点负荷加明确的分车响应干预，逐段另记模拟设备状态和 D02 事件引用。D02 引用只作流程模式来源；除显式状态外，不把另一场景的降额当作本场景已发生设备故障。实际历史充电、电网电量和量测质量只在区间结束后出现；实际净取电与预测基线之差会受未知历史充电和预测误差影响，不能直接解释为市场履约量。缺测时 `grid_import_energy_kwh` 为空且 `measurement_quality=unknown`，不是零。储能本站级 `site_dispatch_ready=false`，不把 2 MW/4 MWh 铭牌当成响应能力。

| 场景 | 技术预期 |
| --- | --- |
| `DR01_normal_down` | 两段各下调 40 kW，末段增加 80 kW，补回车辆电量 |
| `DR02_up_unavailable` | 上调 1000 kW 超过两车可增功率，拒绝 |
| `DR03_down_unavailable` | 无可延后充电、PV/储能可调用资源，拒绝 |
| `DR04_sustained_service` | 三段连续下调后截止前服务电量不足，拒绝 |
| `DR05_recovery_rebound` | 恢复段需 160 kW 车队功率，超过 120 kW 分配上限，拒绝 |
| `DR06_partial_activation` | 只激活第二段，末段补回 10 kWh |
| `DR07_cancelled` | 响应前取消，保留无响应服务 |
| `DR08_baseline_tamper` | 篡改尝试指纹不符，冻结基线不变 |
| `DR09_missing_meter` | 技术服务仍可复算，但净取电缺测，证据不足 |
| `DR10_late_receipt` | 确认回执晚于响应开始，拒绝激活 |

`response_offers.csv` 的市场通知提前量、基线/考核规则均为 `unknown`；`fixture_notice_lead_minutes=15` 仅是本测试的时间假设。`activation_events.jsonl` 保存模拟收到、确认、启动、结束、取消及重复回执，均关联版本、基线指纹和 D02 事件来源。`baseline_mutation_attempts.jsonl` 单列篡改探针，不修改原基线文件。`settlement_reference.json` 无金额、合格判定或允许偏差。

独立校验重新计算 40 行冻结基线指纹、过去数据来源、响应和恢复阶段逐车电量、站级 AC 功率平衡、整窗服务电量、并网/端口上限、事件时间和重复回执，并确认实际真值晚于 `as_of`。`validation_report.json` 的 `passed` 仅证明本技术数据包自洽。
