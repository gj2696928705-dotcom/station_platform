# 滚动事件与故障模拟数据

本包是 `HH-Huanghua-CSS` 的 2025 离线流程测试材料，固定引用 D01 的 `S06_calibration` 四个 15 分钟区间。`simulation_config.json` 固定 D01 及储能来源 SHA-256。所有事件为模拟，不代表真实故障率、保护行为或已认证的设备控制流程。

运行：

```powershell
python -B .\generate_rolling_events.py
python -B .\validate_rolling_events.py
```

`events.jsonl` 保存 22 个场景、152 条按平台接收时间回放的事件；`scenario_manifest.json` 保存事件顺序、预期状态不变量与真值引用；`execution_truth.jsonl` 保存执行后的实际分车电量、储能 AC 功率与电量、并网电量和 SOC；`event_truth.jsonl` 单列量测、故障、预测和连接状态的合成真值，使零执行故障场景也有真值。`validation_report.json` 保存来源/产物哈希、逐场景预期与实际状态、独立算术和回放检查。字段含义见 `字段字典.md`。

每个场景的初始量测取 D01 决策前已结束的 09:45–10:00 区间，预测取 D01 10:00 发布的过去数据基线。计划是两车各 40 kW、储能闲置、PV 全部弃光的**非优化测试桩计划**，仅为执行事件提供固定指纹；不能称为算法最优输出。实际步骤在区间结束后才可见，按 D01 同期真值加明确的执行干预生成。储能偏差场景在首段额外放电 200 kW，其余步骤为闲置。禁止把 `execution_truth` 当作此前预测或量测。

事件时间区分 `business_time`、`measured_at`、`available_at` 与 `received_at`。本夹具将事件的决策可见时间设为平台实际接收时间；独立事后真值可在区间终点成熟，二者不能混用。重复回执保留同一事件 ID、相同业务内容但晚接收，同 ID 内容改变被拒绝。依 `received_at,ordinal` 确定性回放；按 `available_at≤as_of` 截断时，不出现未来执行真值。未知量测使用 JSON `null` 与 `quality=unknown`，不填零。

场景覆盖正常执行、重复/冲突回执、拒绝零执行、SOC/PV/并网变化、迟到取消确认、旧版回执、新量测先到、重启回放、保护/人工接管/冻结、差/过期量测、过期/缺口预测、失联/恢复、重算上限和剩余服务不可行。第二版计划携带第一段执行前缀指纹，取消确认前的第二版发送被拒绝。迟到确认附有站端模拟停机边界与已执行步骤数；未确认前不释放旧占用。

独立校验逐步复算 `并网+PV利用+储能放电=基础+历史充电+分车充电+储能充电`（均按 kWh），以及储能效率与 SOC 更新。正常回放两次状态一致；异常场景的 `expected_status` 和 `actual_status` 在报告中逐项比对。报告通过仅说明事件夹具自洽，不证明实际滚动优化或真实安全放行。评分器必须等真值成熟且质量合格后另行评分；本包不输出实时评分。
