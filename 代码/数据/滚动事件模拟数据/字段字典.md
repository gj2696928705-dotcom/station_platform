# 字段字典

`events.jsonl` 每行均有：`scenario_id` 场景、`event_id` 事件身份、`event_type` 事件族、`station_id` 站点、`asset_id` 资产、`business_time` 业务发生、`measured_at` 量测完成（不适用为空）、`available_at` 业务可见、`received_at` 平台接收、`task_id` 任务、`plan_version` 计划版本（不适用为 0）、`plan_fingerprint` 计划 SHA-256（不适用为空）、`payload` 原始值与质量/有效期、`is_simulated=true`、`source_ref` 来源、`ordinal` 同时刻稳定顺序。所有非空时间均为带 `+08:00` 的 ISO 8601。

`payload` 按事件族包括：

| 事件族 | 主要原始字段 |
| --- | --- |
| `measurement` | `base_kw,pv_kw,grid_kw,soc_percent,equipment_quality,quality,valid_until`；未知值为 `null` |
| `forecast_issued` | `vintage_ids,load_point_kw,pv_point_kw,issued_at,native_grid,coverage_count,quality,valid_until`；逐段原始值引用 D01 已冻结预测 |
| `booking_changed` | `visible_bookings` 的预约 ID/端口/承诺 kWh/可见时间，或新增的 `remaining_energy_kwh,port_max_kw,deadline_at` |
| `derating` | `new_import_limit_kw,quality,valid_until` |
| `protection,manual_takeover,device_frozen,connection_lost,connection_restored` | `active,quality,valid_until` |
| `plan_sent` | `plan`，含版本、整段服务桩计划、已执行前缀指纹；整条计划规范化 JSON 的 SHA-256 是 `plan_fingerprint` |
| `plan_accepted,plan_rejected` | 接受标记或拒绝原因、已执行步数 |
| `step_completed` | `step_index,actual`；`actual` 含逐车 kWh、负荷/PV/储能/并网 kWh、储能 AC kW、新能量/SOC、质量 |
| `cancel_requested,cancel_acknowledged` | 取消原因或确认、实际停机边界与已执行步数 |
| `replan_requested` | 重算次数 |

`execution_truth.jsonl` 每行引用场景、站点、任务、版本、步序、业务时间、可见时间、`actual` 及来源；这些是事后真值。`event_truth.jsonl` 每行包含 `source_event_id,asset_id,state_kind,state_effective_at,truth_available_at,raw_value,quality`，只表示合成场景状态，不是独立现场量测。`scenario_manifest.json` 每项包含场景、任务、窗口、按接收时间排序的事件 ID、预期状态和约束、真值文件引用、模拟标记。`validation_report.json` 的产物哈希不包含报告自身。
