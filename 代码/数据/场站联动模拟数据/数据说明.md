# 黄花站联动模拟数据（2025 离线回放）

本包只用于 `HH-Huanghua-CSS` 的算法接口和约束测试。所有数值均为模拟，`execution_mode=offline_replay`。它不证明真实站点的设备能力、预测精度、经济收益或 2025 年真实投运情况。

## 文件与生成

在本目录运行：

```powershell
python -B .\generate_linked_data.py
python -B .\validate_linked_data.py
```

生成器只读 `代码/数据` 中的四个已有来源包，并在写入前核对 `simulation_config.json` 中 8 个关键源文件的 SHA-256。`source_manifest.json` 另外记录四包的说明、配置、原校验报告和储能轨迹的哈希。所有新文件都留在本目录。CSV 为 UTF-8 BOM、LF 换行；脚本使用 Python 标准库。

| 文件 | 内容 |
| --- | --- |
| `station_interval_truth.csv` | 全年 35,040 个 `[t,t+15min)` 真值区间，包含负荷分量及 PV 数值积分近似 |
| `booking_events.csv` | 独立生成的模拟预约、撤销及到站事件，含可见时间 |
| `vehicle_requests.csv` | 每个场景在决策时刻可见的假设车辆请求 |
| `forecast_vintages.csv`、`forecast_values.csv` | 预测版本元数据、逐区间原生预测与启发式上下界，含不可用版本 |
| `scenario_inputs.csv`、`tariff_intervals.csv` | 决策时可见的窗口约束、设备状态、费率及预测选择 |
| `scenario_truth.csv` | 同窗口事后真值，不能用于特征或候选计划 |
| `source_manifest.json` | 来源文件路径和 SHA-256 |
| `validation_report.json` | 生成哈希和独立复算结果 |
| `字段字典.md` | 字段及单位 |

## 计量和时间口径

- 负荷 `base_load_kw` 排除车辆充电、PV 和储能；`historical_charge_kw` 是已发生的模拟充电支路负荷。`total_load_kw=base_load_kw+historical_charge_kw`，三者都是区间平均值，区间终点之后才完整可见。未来历史充电**未**填入决策输入。
- 原 PV `pv_power_kw` 是时刻采样。派生区间均值为相邻点 `(P_t+P_{t+15})/2`，电量为该值乘 `0.25h`。这是按线性变化的梯形积分近似，并非实测区间均值。最后一个区间引用原 PV 说明中明确的 2026-01-01 00:00 夜间零功率锚点，`pv_right_endpoint_source` 明示该来源；没有伪造 2026 真值行。
- 站级 AC 功率平衡为 `grid_import + pv_used + storage_discharge = base + charging + storage_charge + grid_export`。站点模拟购电上限 10 MW、反送上限 0；PV 超出站内吸收能力时需弃光或另有可行吸收措施。`scenario_truth.csv` 只给不限发 PV 参考出力，不预填优化方案。
- `as_of` 之前仅可读取 `available_at≤as_of` 的事件、费率、静态约束、储能状态和预测。`scenario_truth.csv` 的 `available_at` 为区间终点。所有时间为 `+08:00`、15 分钟连续网格。

## 预测与预约的适用范围

预测用过去一周同槽基础负荷及前一天同槽 PV 区间近似值构造，原生网格均为 15 分钟区间平均。输入区间均在 `issued_at` 前结束，且 `issued_at=as_of`。上下界是配置中的启发式宽度，**没有校准覆盖率承诺**。该基线仅覆盖各场景 4 个区间，不延伸成全天预测。

已有负荷和 PV 模型是 2026 年生成的候选包，不能称作 2025 年当时发布的预测。特别是 PV day13 需要同一完整的未来 13×4 天气预报批次，且批次发布时间不晚于 `min(as_of,D日07:00)`。本项目没有这样的 2025 历史预报批次。本包没有使用当天已实现天气来冒充预报，也未运行该候选模型。`S12_late_weather` 给出晚于 07:00 的假设批次，明确标记不可用；`S11_pv_gap` 的选中版本只覆盖 2/4 区间，也不可用。其他场景明确选用过去数据基线；全天优化需单独提供完整预测及适用范围。

预约是**独立的反事实事件过程**：每个场景从决策前七天内已结束的会话选取三个不同端口的请求电量作为模板，生成全新 `BOOK-...` 会话编号。预约于 `as_of-60min` 发生、`as_of-30min` 可见；第三个在 `as_of-5min` 撤销；前两个在 `as_of+15min` 产生到站事件。决策时只有未撤销且已可见的预约能算模拟既有承诺。原始未来会话的 ID、结束时间和最终功率均不进事件或决策输入。`S10_no_booking` 的既有承诺状态为 `unknown`，不能用未来会话补齐。即使有预约，也不能从承诺电量直接推断逐区间充电功率。

## 场景、假设与验证边界

12 个窗口覆盖晴天、峰值错位、并网约束、并发、PV 过剩、储能贴底/贴顶、设备降额、无预约、预测缺口和晚发天气。窗口从已知模拟真值中**事后确定**以制造压力样本；`expected_constraint` 仅说明应检查的硬约束，不给最优方案。`development`、`calibration`、`replay_evaluation` 依时间先后标注，但既有模型开发已接触 2025 数据，且窗口事后挑选，因此最后一组也不是全新盲测。

费率是 2025 全期有效的示例分时购电价格，单位 CNY/kWh：00–07 与 23–24 为 0.4，07–17 为 0.8，17–23 为 1.2；禁止反送，售电价格为 0。车辆请求每车 50 kWh、240 kW 上限，是独立假设请求，不等同历史会话。静态设备来自已有台账；`S09` 假设一个端口降至 120 kW、PCS 降至 1 MW。储能初态除原包 2025-01-01 的 60% 外均为各窗口新模拟状态；30%/90% 用于边界场景，不从原局部轨迹推断。效率 0.95、备用下限 30%、上限 90%、下个本地午夜 60% 目标引用原储能参数；`site_dispatch_ready=false` 保留。四区间窗口不能单独证明午夜目标可达。

独立校验重新读取原始文件：35,040 行负荷守恒及 PV 积分、128 端口会话不重叠、事件可见性、预测只取过去数据、窗口真值晚于决策、费率、原储能轨迹 202 个被接受步骤的能量更新，并抽查 6 个时段的零反送功率平衡。报告的 `passed` 仅表示此模拟包自洽。
