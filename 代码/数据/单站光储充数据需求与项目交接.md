## 3. 七组数据共用的契约建议

### 3.1 通用字段与时间

以下为后续统一层的建议，现有CSV不要求立刻改写；可通过适配器保留原始值并增加元信息。

| 字段或信息 | 含义及要求 |
| --- | --- |
| `station_id`、`asset_id` | 站点和可选设备标识；年度数据与平台节点需要显式映射，不能只改名便视作同一套资源 |
| `dataset_id`、`schema_version`、`config_version` | 数据、结构和场景参数版本；保存原始文件哈希及转换过程 |
| `source_type`、`is_simulated` | 来源类型与模拟属性；模拟/实测来源和数据质量是不同维度 |
| `value`、`unit`、`value_semantics` | 数值、单位及瞬时值/区间平均功率/区间电量等含义 |
| `observed_at`或`interval_start/end` | 事实发生时刻或统计区间；统一保留时区，区间采用左闭右开语义 |
| `available_at` | 这条信息最早能被规划使用的时间，不自动等同于区间起点 |
| `ingested_at` | 系统实际收到并保存记录的时间，用于分析迟到数据 |
| `issued_at`、`valid_from/to` | 报告发布时间及适用范围；预测还需要目标时间和输入截止时间 |
| `quality_flags` | 缺失、迟到、过期、异常、推算、替代等标记；缺失值不能自动填成0 |
| `task_id`、`plan_id/version`、`snapshot_ref` | 任务相关对象的关联信息，用于冻结输入和追溯结果 |

业务时钟负责历史回放与模拟时段，实际时钟负责进程心跳、请求超时和记录时间。使用2025年回放数据时，要明确回放截止时刻；不能用当前实际日期判断所有历史输入失效，也不能把历史文件末尾的预测标为实时预测。

### 3.2 单位、计量与可用性

- 功率使用kW，电量使用kWh，时间步长参与计算时使用小时；15分钟对应0.25h。
- SOC明确使用0—100的百分数还是0—1的比例；建议对外使用带`percent`后缀的百分数，效率使用0—1，并在适配时显式转换。
- 购电、售电及储能充放电建议分别记录非负值；若另提供有符号净功率，写明正负方向及计量位置。
- 车辆需求、电表读数、充电支路用电和电池实际入电量应分别说明口径。现有充电模型未建立充电损耗，不能自动把它们视为未来系统的同一个量。
- 参数表、预测、设备状态和服务承诺均需有效期或版本。缺少关键边界时报告不可用或受限，不由Agent补出一个数值。

## 4. 七组详细数据需求

### 4.1 第一组：场站与设备台账

**用途**：建立统一资源清单、功率共享关系和计量边界，使预测、优化与站端校验使用同一套设备及限制。

**现有来源**：两组年度数据的`simulation_config.json`及平台`legacy/demand.py`中的默认设备、能源与安全配置。现有资料提供部分模拟规模，未提供完整真实台账。

| 建议字段 | 单位/时间含义 | 必要性与缺项 |
| --- | --- | --- |
| `station_id/name`、`timezone` | 标识、名称、时区 | 必需；已有两套模拟身份，需映射 |
| `asset_id/type`、`parent_asset_id`、`port_id` | 设备类型及上下级/枪口关系 | 必需；补充桩、枪、PCS、储能、光伏与电表的对应关系 |
| `rated_power_kw`、`max_available_power_kw` | 额定值与当前可用上限 | 必需；可用上限随故障、降额及有效时段变化 |
| `shared_limit_group`、`shared_limit_kw` | 多枪/多设备共享限制 | 存在共享关系时必需，不能把所有枪额定值直接相加 |
| `grid_import_limit_kw`、`grid_export_limit_kw`、`export_allowed` | 并网购售电边界 | 必需；实际来源或模拟依据、有效期必须明确 |
| `meter_id`、`measurement_boundary` | 总表、基础负荷、充电、光伏、储能支路的覆盖范围 | 必需；避免重复计量和损耗重复计算 |
| `availability`、`derating_reason`、`effective_from/to` | 可用、故障、检修、降额及持续区间 | 必需；需补充时间化状态 |
| `protection_active`、`manual_takeover`、`frozen_assets` | 保护、人工接管和冻结设备 | 必需；平台已有简化字段，未来与新设备模型对齐 |

**补充方式建议**：先建立一个版本化模拟场站参数表，选择与年度数据相容的规模或显式转换规则；将资产、共享限制及计量拓扑分别登记。真实参数取得后另建来源版本，不直接覆盖模拟依据。

### 4.2 第二组：能源时序数据

**用途**：为预测、状态回放、资源能力和优化效果计算提供统一输入与实测/模拟对照。

**现有来源**：光伏和负荷年度主CSV、月度统计及校验报告。两份主表均覆盖2025年，每15分钟一行；尚无完整并网进出电与储能时序。

| 字段 | 单位/时间含义 | 已有与待补充 |
| --- | --- | --- |
| `pv_power_kw` | kW，采样时刻瞬时功率 | 已有；不能直接视为15分钟平均功率 |
| `base_load_kw` | kW，区间平均；不含充电、光伏、储能 | 已有；负荷模型默认预测目标 |
| `charging_load_kw` | kW，区间平均充电支路用电 | 已有历史模拟值，不能当作未来计划 |
| `total_load_kw` | kW，基础负荷＋充电负荷 | 已有；未扣光伏/储能，不是并网净负荷 |
| `grid_import/export_kw`及区间电量 | 并网点平均功率和kWh | 待补；若由能量平衡推算，标明派生来源而非独立电表测量 |
| `storage_charge/discharge_kw` | AC侧区间平均充放电功率 | 待补；与储能状态同步 |
| `pv_available/used/curtailed_kw` | 可用、利用和弃光功率 | 待补；年度光伏默认未建限发/故障模型 |
| 数据质量、可用时间、迟到情况 | 逐点或逐区间 | 现有年度数据较完整；需补异常测试样本，不能只测理想数据 |

**转换规则**：历史光伏区间电量可用相邻点梯形积分近似`(P(t)+P(t+15min))/2×0.25`，但只有右端点可用后才能形成已完成区间的结果；负荷区间电量直接用平均功率乘0.25，不能再做梯形积分。回放中不得读取尚未到达的下一点；未来光伏点预测如何转成优化用区间量需单独定义，并保留积分假设。

**补充方式建议**：建立只读适配与历史回放层，保留原始文件；输出统一的区间平均功率/电量及转换元数据。补充缺测、迟到、光伏突降和限发场景；独立保留“可见输入”和“事后评价真值”。

### 4.3 第三组：车辆需求与服务承诺

**用途**：明确必须在何时为哪些车辆交付多少电量，计算剩余需求、分桩及可调整空间。

**现有来源**：`充电会话明细.csv`含`session_id, station_id, is_simulated, session_type, port_id, arrival_at, start_at, end_at, duration_minutes, queue_minutes, peak_power_kw, requested_energy_kwh, charging_energy_kwh, energy_in_2025_kwh`。平台任务表单另有车辆编号、需求电量、到离站相对分钟及关键/普通优先级。

| 建议字段 | 单位/时间含义 | 必要性与缺项 |
| --- | --- | --- |
| `vehicle_id`、`session_id`、`known_at` | 车辆/会话及需求最早已知时间 | 必需；历史会话标识已有，需区分订单预告与实际到站 |
| `arrival_at`、`expected_departure_at` | 实际到站与计划时已知的预计离站 | 必需；CSV的实际充电结束时间不能直接替代预计离站 |
| `requested_energy_kwh`、`energy_basis` | 需求电量及支路/电池侧口径 | 必需；现有CSV有需求值，但需明确新优化所用计量侧 |
| `delivered_energy_kwh`、`remaining_energy_kwh` | 截止当前已交付及剩余量 | 必需；按有效执行回执累计，不能使用最终全会话电量代替当前值 |
| `soc_percent`、`battery_capacity_kwh` | SOC和车辆电池容量 | 使用SOC/电池模型时必需；仅按支路电量服务时可明确不用，不能猜测 |
| `max_charge_power_kw`、`charge_curve_ref` | 当前受电上限或SOC相关曲线 | 必需上限；曲线可分阶段建设，历史峰值不等于实时受电能力 |
| `connector_type`、`allowed_ports` | 接口与设备兼容性 | 分桩时必需；平台当前统一DC为简化假设 |
| `priority`、`commitment_version`、`minimum_delivery_kwh` | 优先级、承诺版本与最低交付 | 必需；优先级对应硬约束或软惩罚需确认 |
| `interruptible`、`deferrable`、`max_delay_minutes` | 可中断/延期与边界 | 若允许灵活调度则必需，不能默认所有车辆均可调 |
| `assigned_port`、`current_status`、`accepted_plan_ref` | 当前分配、执行状态及已接受计划 | 增量规划必需，防止已执行或已承诺部分重复分配 |

**补充方式建议**：基于历史会话另建“决策时可见需求/承诺”表，实际结束、最终电量保留在评价表；为预计离站、SOC、灵活性等缺项单列模拟规则和随机种子。跨年会话要保留真实覆盖区间，`energy_in_2025_kwh`只是落在2025年的电量，不是整单需求。

**当前接口差异**：现有迁移适配器要求既有负荷计入其`base_load_kw`；年度负荷CSV中的同名字段却明确排除充电。统一层必须把基础负荷、不可重排的既有充电、可优化剩余需求分开，再映射到旧接口，避免漏算或重复算既有充电。

### 4.4 第四组：储能参数与实时状态

**用途**：计算储能在目标时段的充放电能力、能量边界与备用，支撑光储充联合优化及站端独立校验。

**现有来源**：平台默认仅有500kWh、SOC60%、保留SOC30%及`idle`等简化数据，没有可供联合优化使用的完整储能数据组。这些数值不是实站确认参数。

| 建议字段 | 单位/时间含义 | 必要性与缺项 |
| --- | --- | --- |
| `storage_id`、`pcs_id`、`soc_reference_capacity_kwh` | 身份及SOC计算所对应的参考容量 | 必需；区分额定容量、当前有效容量和SOC窗口内可调电量 |
| `usable_capacity_kwh`、`soh_percent` | 当前可用容量及健康状态 | 可用容量必需；SOH若已折算进容量，不再重复折减 |
| `soc_percent`、`measured_at`、`available_at` | 截止规划时可用的SOC | 必需；状态须随模拟执行更新，不能每次重置为初始值 |
| `soc_min/max_percent`、`reserve_soc_percent` | 运行上下限和备用要求 | 必需；备用与运行下限的组合规则需明确 |
| `max_charge/discharge_kw`、`pcs_limit_kw` | 当前充放电及PCS上限 | 必需；包含故障/温度等降额后的有效值 |
| `charge/discharge_efficiency` | 0—1；定义AC侧功率与电池能量之间转换 | 必需；不能只给未分解的往返效率却任意拆分 |
| `dispatch_status`、`fault`、`manual_lock` | 可调、故障、锁定及有效时段 | 必需；不可用时不安排充放电 |
| `terminal_soc_target`及目标时刻 | 规划末端SOC要求 | 比较方案及滚动衔接必需；数值/硬软约束待确认 |
| `throughput_cost`、自放电、爬坡限制 | 元/kWh及相应动态约束 | 按评价与设备模型补充；未建模的项目应列明 |

**动态模型建议**：统一AC侧非负充放电功率，电池能量按`E(k+1)=E(k)+η_charge×P_charge×Δt−P_discharge×Δt/η_discharge`更新；SOC与能量换算采用已确认的参考容量。同一储能同一时段不得同时充放电。可调能力还应扣除备用、既有承诺和有效设备限制。

**补充方式建议**：先准备独立储能参数表、初始状态及逐时段状态轨迹；功率、效率、SOC上下限、备用和末端目标均标记为待确认模拟参数。参数齐备后再开发资源计算与执行更新，不能只在Agent职责中写“考虑储能”便视为已实现。

### 4.5 第五组：电价与经济评价口径

**用途**：让方案比较使用同一时段价格和费用边界，给出可追溯的成本，而不是由模型估计收益。

**现有来源**：平台默认四时段购电价`[0.4,0.4,1.2,1.2]元/kWh`；目前比较充电候选的购电成本及光伏利用等结果，未形成完整商业收益模型。

| 建议字段 | 单位/时间含义 | 必要性与缺项 |
| --- | --- | --- |
| `tariff_id/version`、`station_id`、`valid_from/to` | 适用站点、版本及生效区间 | 必需；历史回放使用当时适用版本 |
| `period_start/end`、`purchase_price` | 时段与元/kWh购电价 | 必需；明确是否含税、输配及其他费用，覆盖全部优化区间 |
| `export_allowed`、`export_price` | 是否售电与元/kWh售电价 | 允许售电才启用；当前默认不反送，不能自动加入售电收益 |
| `charging_revenue_rule`、`service_fee` | 充电收入及服务费 | 计算经营净收益时必需，只有购电成本时不宣称净利润 |
| `loss_basis`、`storage_throughput_cost` | 充电/储能损耗及吞吐成本 | 启用相应模型时补充；避免损耗电量或费用重复计入 |
| `demand_charge_rule`、`historical_monthly_peak` | 需量费用规则及历史月峰 | 若纳入需量评价则必需；单小时规划不能自行推断月度节费 |
| `baseline_policy`、`baseline_version` | 对照策略与可重复计算参数 | 必需；明确先到先充、原计划等哪个对照，不能只给“节省比例” |
| `terminal_energy_value`或一致末端约束 | 剩余储能的统一价值/约束 | 储能方案比较必需；防止把用尽初始电量误算成运营节省 |

**补充方式建议**：先形成完整覆盖回放窗口的模拟分时电价表和费用口径表，用户确认后冻结版本；成本、收入、净收益分别展示。未知费用列为未纳入项，不能默认为已完整覆盖真实结算。

### 4.6 第六组：天气与预测输入、预测结果

**用途**：为模型提供决策时真实可见的信息，并把输出转换成可追溯的资源输入。

**现有来源**：光伏CSV含`SWGDN,DHI,DNI,temperature_c,rain,cloud_cover,weather_type,solar_elevation_deg`；它们来自合成天气过程。负荷温度复用该表，周末仅表示周六/日，不包含节假日调休。

| 建议字段 | 单位/时间含义 | 必要性与缺项 |
| --- | --- | --- |
| 历史辐照、温度、云量、降雨 | W/m²、℃、0—1、mm/区间 | 按所选模型元数据提供；原列含义不能混换 |
| `issued_at`、`target_time/interval`、`forecast_batch_id` | 天气预报发布时间、目标时间、批次 | 使用未来天气时必需，当前同步天气不是这类预报归档 |
| `provider`、`forecast_variable/unit` | 预报来源、变量与单位 | 使用预报时必需；用于重现数据版本 |
| `model_id/version`、`bundle_ref/hash` | 模型身份和冻结产物 | 预测接入必需；明确主模型与降级基线 |
| `forecast_origin`、`input_cutoff/available_at` | 预测起点及可用输入截止 | 必需；不晚于当次决策可见信息 |
| `target_start/end`、`interval_minutes`、`target_semantics` | 目标区间、粒度、瞬时/平均功率 | 必需；光伏点输出与负荷区间输出分别适配 |
| `prediction/lower/upper`、`interval_definition` | kW、点预测与区间定义 | 点预测必需；若使用区间边界，应记录名义覆盖和校准来源 |
| `publication_status`、`execution_mode`、`quality/status` | 候选/发布、回放/在线、可用/降级/不可用 | 必需；仿真使用资格需显式记录，不能改写成生产发布 |

**时间纪律**：`rain`是`[t,t+15min)`累计降雨，在区间结束后才完整可知；不能在t时刻作为已知实测特征。未来天气须取预测起点前已发布且覆盖目标范围的批次；历史回测要用当时的预报归档，不能用事后同步天气代替。

**现有预测接口差异**：负荷的`forecast_end_at`是末区间排他终点；光伏点预测的末点与区间终点不能直接按同名字段拼接，应核对所选包实际输出。还要保留训练、选模和校准截止时间；不能将利用全年2025年数据选出的候选包回放到其尚未训练完成的2025年早期，再声称当时可部署预测。

**补充方式建议**：首期可继续采用历史功率、历史气象及未来日历/太阳位置，不以获得真实未来天气为前提。只有确认启用未来天气时才补预报归档。模型加载只读，主模型、基线、特征列、缩放器和区间校准按包一起恢复；缺模型或必要输入时明确返回不可用。

### 4.7 第七组：计划、执行反馈与异常事件

**用途**：回答计划为何产生、站端是否接受、实际完成多少、为何重算及剩余义务是什么。

**现有来源**：中心与站端SQLite中的任务、工具记录、计划和逐时段模拟回执；已有容量下降、桩故障、保护、心跳暂停、量测过期及电价变化等模拟场景。

| 建议字段 | 单位/时间含义 | 必要性与缺项 |
| --- | --- | --- |
| `task_id`、`plan_id/version`、`parent_plan_ref` | 任务、计划、版本及替代关系 | 必需；旧版本保留，不能重算后覆盖证据 |
| `state/forecast/demand/tariff/model_refs` | 输入、预测、承诺、价格及模型版本 | 必需；新增预测/储能后扩展追溯信息 |
| `station_id`、`asset_id`、`slot_start/end` | 接收节点、设备和执行区间 | 必需；与有效计划绑定 |
| `received/accepted/rejected/started/completed` | 各阶段状态及发生时间 | 必需；接收成功不等于执行完成，拒绝需原因 |
| `scheduled/actual_power_kw`、`actual_energy_kwh` | 计划/实际平均功率及电量 | 必需；补充储能功率、SOC及车辆分配结果 |
| `receipt_id`、`idempotency_key` | 回执和重复请求保护 | 必需；重复发布、推进或回执不能重复交付电量 |
| `event_type`、`observed/available_at`、`severity` | 事件类型、发生/可见时间与影响级别 | 必需；支持故障、降额、通信、人工接管和承诺变化 |
| `business_time`、`recorded_at` | 模拟业务时间和实际记录时间 | 必需；加速执行耗时不能作为实站响应性能 |
| `remaining_obligation`、`replan_reason`、`gap` | 剩余服务承诺、重算原因及缺口 | 增量规划必需；不可满足时留下明确缺口 |

**补充方式建议**：沿用平台现有持久化和幂等机制，补充储能SOC轨迹、车辆累计交付、电价/模型版本引用及事件回放。部分执行后的新计划只作用于未执行部分，保留原回执；断线或重启后不能从零再次执行原始全部需求。

## 5. 跨组约束与常见失败场景

### 5.1 功率和能量平衡

后续联合优化建议统一AC计量边界，按每个区间检查：

```text
购电功率 + 已利用光伏功率 + 储能放电功率
    = 基础负荷 + 全部已计入的充电功率 + 储能充电功率 + 售电功率

可用光伏功率 = 已利用光伏功率 + 弃光功率
区间电量 = 区间平均功率 × 区间小时数
```

上述是建议模型，不是现有平台已经实现的储能调度。若设备效率与电表不在同一计量边界，应增加显式损耗项；不能一边将损耗算进支路功率，一边再次加同一损耗。当前默认不反送时，售电应为0，剩余光伏计弃光。

基础负荷、固定既有充电、可重排已有需求和新需求应有互斥归属；同一会话的同一段电量只能计入一次。若使用`total_load_kw`预测，必须重新界定其中充电部分，不能再简单叠加全部充电计划。

### 5.2 评价公平性与证据边界

- 对照和优化方案使用相同车辆、资源、信息可见范围、初始SOC及服务承诺；末端采用一致SOC约束，或显式核算剩余电量价值。
- 同时展示成本、购电量、弃光/光伏利用、按时交付率、缺口、储能吞吐及末端SOC，不能只报告一个“节费率”。
- “资源不足”“模型不可用”“搜索达到上限”“优化不可行”“接口故障”是不同原因，应分别记录；搜索未找到不等于已证明无解。
- 未来实际光伏/负荷、实际离站及最终电量只能用于事后评价，不能出现在决策输入里。
- 同一模拟器的新随机轨迹可以补软件与分布测试，但不等于独立真实场站验收；模拟好成绩不能证明生产收益。

## 6. 建议实施顺序与阶段产物

以下均为待实施方向，先核对并确认第8节事项后，再按授权范围开发。

| 阶段 | 工作与边界 | 可检查的交付物 |
| --- | --- | --- |
| A：数据基础 | 统一场站规模、计量口径、可见时间、缺失策略与历史回放；保留原始数据 | 数据字典、缺项表、模拟场站参数、字段映射、回放场景及版本清单 |
| B：预测与资源 | 为O2接入只读光伏/基础负荷预测工具；加入储能当前及未来能力计算 | 带输入截止/版本的预测记录、分时资源边界、SOC可用能量及不可用原因 |
| C：光储充联合优化 | 为O3增加确定性联合优化及独立评价；保留车辆承诺、设备、并网、SOC及备用约束 | 充电与储能计划、SOC轨迹、约束校验、对照结果及可追溯计算记录 |
| D：剩余需求滚动 | O1按事件及周期触发；S1更新实绩；只规划未执行部分，保护既有承诺 | 重算原因、新旧计划关联、累计交付、缺口和幂等/重启验证 |
| E：网页与观察 | 展示历史/预测/计划/实际曲线、质量、版本和各类成本 | 曲线、任务详情、输入证据、角色/工具阶段、实际请求耗时及失败原因 |

建议第一批数据准备成果是：**数据字典、模拟站点参数表、需求/承诺表、储能参数表、电价与评价口径表、验收场景表**。本文件列出需求，不表示这些表或新CSV已经生成。

Agent边界继续保持：S1组织本站事实、校验与反馈；O1统一任务和计划发布；O2组织预测与资源评估；O3组织优化和评价；O4保持模拟外部业务条件与履约反馈。新增模型和计算器作为工具，不因功能增加就新增Agent。

## 7. 后续验收场景

| 场景 | 应检查的结果 |
| --- | --- |
| 正常光储充规划 | 每时段功率平衡、设备/并网边界、车辆期限、SOC上下限及末端目标均可复算 |
| 分时电价变化 | 使用生效版本重算，旧任务保留旧价格与证据；费用计算与时段一致 |
| 光伏突降、负荷上升 | 更新预测/资源，报告影响；重算不能突破购电、设备或服务边界 |
| 紧急补能或预计离站变化 | 更新需求/承诺版本，累计已交付不丢失；不足时明确缺口 |
| 枪口故障或共享功率降额 | 受影响设备不再分配；共享功率不能按单枪额定值重复累加 |
| 储能低SOC、故障、降额 | 不越SOC/功率/备用限制；故障设备无充放电；不存在同时充放电 |
| 能源与充电计量重叠 | 基础、既有、新充电量互不重复；总负荷与净负荷区分正确 |
| 缺测、迟到、过期、预报批次缺失 | 不用未来记录补历史；必要输入不足时明确不可用/受限及降级依据 |
| 回放信息泄漏 | 修改预测起点之后的标签，不应改变此前决策输入；事后离站不进入当时承诺 |
| 部分执行后重算 | 旧回执保留，只处理剩余电量与未来时段，已完成部分不再执行 |
| 重复发布、重复回执、服务重启 | 不重复执行/累计电量；计划版本与中断状态明确 |
| 储能经济对照 | 相同初始和一致末端口径下比较；不将耗尽初始储能误记为节费 |
| 候选模型与真实调用 | 测试替身、模拟业务、候选算法和真实模型调用分别标注；失败不伪造成功 |

数值误差容差、允许缺口、预测误差门槛、求解时限及可接受成本等验收阈值尚未确认，应在开发前结合所选数据和算法制定，不在本文虚构已通过指标。
