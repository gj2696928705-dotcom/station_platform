# 负荷预测算法与平台适配验证

日期：2026-10-27。先阅读根目录交接文档，再检查实际源码、原始数据和模型，按“算法 → 平台适配”的顺序验证。

## 结论

**算法设计可作为当前模拟场景的候选方案；经修复后可稳定加载、复验。具备平台适配可行性，但现有平台尚未正式接入。**

- 全年默认配置重新训练，180轮早停、最佳150轮，权重SHA-256与原包完全相同；原包完整测试指标和96个提前步长的独立校准分位数均复现。
- 1,291个整点起点、123,936个“起点×提前步长”的测试结果：RMSE 25.7098 kW、MAE 21.2282 kW、R² 0.965920，相对前周同刻基线的RMSE降低33.01%。
- 算法25项测试通过；平台适配隔离探针14项检查通过；平台完整43项回归通过（142.18秒），使用本机隔离QA目录和明确的模型替身，不证明真实大模型API可用。日志见同目录 `platform_tests_verified.log/.xml`。
- 只验证2025年合成数据上的实现与性能。没有实测场站精度证据，没有2026-10-27当前历史数据，也未完成模型发布、真实站点绑定或线上调用链。

## 3. 本次定位并修复的问题

### 3.1 Windows中文路径重载失败

本机XGBoost CPU 3.4.1，直接 `Booster.load_model(Path(...中文路径...))` 发生 `UnicodeDecodeError`。同一文件通过Python读取为 `bytearray` 后加载成功，150棵树完整恢复。最初原有21项测试实际为20通过、1失败；不能沿用旧文档“21项通过”作为本次结果。

修复：保留文件SHA-256校验，改为Python读取原始权重字节后调用XGBoost加载。不改变特征、参数、训练目标或旧模型包。中文路径重载、损坏权重拒绝均重新验证。

### 3.2 输出契约校验不足

修改前，错误单位W、interval=30、未知负荷口径、错误forecast_type都能通过 `validate_record`；证据见 `initial_record_validation.json`。

修复：检查schema/type、15分钟粒度、时区、网格、排他终点、kW、有限非负数、区间包络、名义覆盖率、候选身份、不可用时空点值/空区间与原因。模型包也检查历史/预测长度、采样间隔、目标口径、校准维度与覆盖率；常见损坏结构转为明确 `unavailable`。新增4个测试方法及多组反例，现25项全部通过。

## 4. 平台适配结果

**“可以做适配”与“平台已接入”必须分开。** `domain.resources/capability`仍为 `forecast_status=not_used`；在 `forecasts` 放记录不会改变负荷计算。未修改平台运行代码、数据库、角色正文或现场设备链路。

| 接口维度 | 当前事实 | 适配要求/验证 |
| --- | --- | --- |
| 环境 | 平台venv无numpy/pandas/xgboost；模型依赖位于数值环境及负荷`.deps` | 平台venv启动独立数值进程真实推理成功；可保持环境隔离 |
| 时间 | 模型固定15分钟网格；平台按业务发起时刻划分4个15分钟段，可能含秒 | 探针验证00:07:30起点重叠加权和00:15整刻切片；必须完整覆盖，无补零 |
| 负荷口径 | 模型base排除充电；平台legacy约定既有负荷计入base | 平台base = 模型base + 独立既有充电预测；新充电计划再单独叠加 |
| 站点 | 模型HH-Huanghua-CSS，平台mock-station-001 | 不一致默认拒绝；探针显式simulation_only绑定，不构成同一真实站点证明 |
| 候选状态 | publication=candidate、decision_eligible=false | 只读/影子展示可推进；正式决策消费需要额外仿真启用契约及发布门禁 |
| 资源消费 | 资源、编排、评价分别读取快照energy；只改resource结果不足以改变其他消费者 | 隔离冻结同一energy序列后，三者和capability/local check共同通过 |
| 现场边界 | 实时状态另行校验 | 降低现场并网容量后阻断；降低计划容量也阻断，不裁剪候选假装可行 |
| 故障 | 无当前数据、缺包、错误输出或超时 | CLI对过期/缺包返回2和unavailable；探针拒绝单位、口径、点数、时钟、覆盖和无绑定 |

真实子进程历史回放含CSV读取、绘图、导入和推理约3.98秒，仅一次本机观测，不是延迟SLA。超时30秒为探针参数。超时实验在真实子进程启动阶段使用1ms限制，验证调用方得到超时而不会继续消费旧文件。

隔离正向探针使用10 kWh测试订单、原模拟500 kW并网边界、原模拟PV；既有充电 `[20,30,40,50]` kW为显式测试假设。投影base为 `[438.394,441.765,442.995,446.558]` kW，加既有充电后为 `[458.394,471.765,482.995,496.558]` kW。资源/编排/评价/本地校验通过；这不代表HH站与500 kW模拟站在物理规模上等价。

非整刻加权采用区间内常值假设；加权后的上下界不自动保留名义80%覆盖率。文件冻结重载只是JSON往返检验，没有完成平台SQLite任务版本持久化。现场校验使用测试内显式历史时钟，未伪造当前实况。

## 5. 待实现的正式接入

1. 独立环境只读调用封装，显式as_of、输入窗口、模型/输入哈希、超时、标准输出校验；不能使用会训练的 `运行.py`。
2. 真实站点和计量边界绑定；准备最新连续7天已完成区间与独立既有充电序列。不得直接把历史CSV中的未来充电实测当预知输入，也不得将总负荷模型重复叠加新充电计划。
3. 固定任务/计划版本的原始预测和适配上下文，提供shadow展示、不可用原因及持久化；`disabled/shadow/simulation_use`仍是拟议模式。
4. 仿真启用时让resources、capability、schedule、evaluation共同消费冻结上下文；现场量测、并网/设备/保护限制继续独立核验。
5. 完成工具说明、角色文档发布、UI、HTTP闭环、重启恢复和发布/回退验收；模型与数据当前被根Git忽略，单独安装平台不会带上它们。

## 6. 复现命令与证据

在项目根目录用PowerShell执行。算法脚本从自身位置解析输入，不依赖当前目录；完整重训结果目录必须是新的空目录。

```powershell

$env:TEMP = Join-Path (Get-Location) '开发验证/20261027_review/temp'
$env:TMP = $env:TEMP
& 'D:/Anaconda3/anaconda/python.exe' -X utf8 -m unittest discover -s tests -v
Pop-Location

# 完整重训+复算；再次执行须换一个新的output-dir
& 'D:/Anaconda3/anaconda/python.exe' -X utf8 `
  '代码/负荷/开发验证/20261027_review/verify_algorithm.py' `
  --output-dir '代码/负荷/开发验证/另一次复验/evidence' --retrain

# 平台环境调模型环境，隔离验证14项
& './station_platform/.venv/Scripts/python.exe' -X utf8 `
  '代码/负荷/开发验证/20261027_review/platform_probe.py' `
  --python 'D:/Anaconda3/anaconda/python.exe' `
  --output-dir '代码/负荷/开发验证/另一次复验/platform'

# 平台回归：固定隔离临时目录，需要允许本机模拟HTTP服务/回环连接
& './station_platform/.venv/Scripts/python.exe' -X utf8 -m pytest station_platform/tests -q `
  --basetemp='代码/负荷/开发验证/另一次复验/platform_temp'
```
